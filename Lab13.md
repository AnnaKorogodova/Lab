# Администрирование кластера docker swarm
## Практические задания
### 1. Создание мастер-ноды и трех воркер-нод с 6 репликами сервиса containous/whoami
На первой машине (или в первой виртуальной машине) инициализируем Swarm:
```sh
docker swarm init
```
Это создаст мастер-нод, и будет выведена команда для добавления воркер-нод в кластер. Пример вывода:
```sh
docker swarm join --token <token> <master-node-ip>:2377
```
На остальных машинах (или виртуальных машинах) выполняем команду для присоединения их как воркер-нод:
```sh
docker swarm join --token <token> <master-node-ip>:2377
```
После того как все ноды добавлены в кластер, мы можем запустить сервис с 6 репликами:

Создадим ```docker-compose.yml``` файл, который будет запускать сервис с 6 репликами:
```sh
version: '3.8'

services:
  whoami:
    image: containous/whoami
    deploy:
      replicas: 6
      resources:
        limits:
          cpus: '0.1'
          memory: 50M
      placement:
        constraints: [node.role == worker]
```
Теперь запустим сервис:
```sh
docker stack deploy -c docker-compose.yml whoami
```
Проверим, что сервисы запущены на разных нодах:
```sh
docker service ps whoami_whoami
```
### 2. Повышение воркер-ноды до мастера, а первую ноду мастера — до воркера
Для того, чтобы повысить worker-ноду до мастера, выполним команду:
```sh
docker node promote <worker-node-id>
```
Для понижения первой мастер-ноды до воркера:
```sh
docker node demote <master-node-id>
```
Проверить статус нод можно командой:
```sh
docker node ls
```
### 3. Выключение ноды и перераспределение контейнеров
Для принудительного выключения ноды (удаления ее) выполним команду:
```sh
docker node rm <node-id> --force
```
Проверить перераспределение контейнеров можно командой:
```sh
docker service ps whoami_whoami
```
Docker Swarm автоматически перераспределит контейнеры по оставшимся нодам.
### 4. Добавление новой воркер-ноды и перераспределение контейнеров
Для добавления еще одной воркер-ноды выполняем на новой машине команду:
```sh
docker swarm join --token <token> <master-node-ip>:2377
```
Провим перераспределение контейнеров:
```sh
docker service ps whoami_whoami
```
### 5. Создание произвольного сервиса с политикой обновления
Создадим новый сервис, например, с образом nginx, и добавим политику обновления.
```sh
version: '3.8'

services:
  nginx:
    image: nginx
    deploy:
      replicas: 3
      update_config:
        parallelism: 1
        delay: 10s
        failure_action: rollback
        monitor: 20s
```
Параметры ```update_config``` контролируют, как сервис будет обновляться:

  ```parallelism```: сколько контейнеров обновлять одновременно (в данном случае — 1).
  
  ```delay```: задержка между обновлениями контейнеров.
  
  ```failure_action```: действия при сбое обновления (в данном случае — откат).
  
  ```monitor```: время для проверки состояния обновленного контейнера.
  
Теперь применим этот файл:
```sh
docker stack deploy -c docker-compose.yml nginx_service
```
Чтобы убедиться, что все обновления применены правильно, можно использовать команду:
```sh
docker service ps nginx_service_nginx
```
Таким образом, мы создадим кластер с мастер-нодой и воркер-нодами, а также будем управлять контейнерами, выполняя масштабирование, обновление и перераспределение контейнеров в кластерной среде Docker Swarm.
