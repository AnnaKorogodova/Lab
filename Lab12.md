# Использование Docker swarm и секретов
Docker swarm фактически является расширением docker обеспечивающее окрестрацию приложений внутри кластера и имеет отличительные особенности, которые управляют репликами приложений.
## Практические задания
### 1. Создайте собственный стек, подобный примеру.
Для создания нашего стэка я возьму в качестве примера compose файл для node js web server, который прослушивает порт 4003:
```sh
# docker-compose.stage.yaml

version: "3.9"

services:
  back:
    image: docker-registry.ru:5000/ptm:stage
    ports:
      - "4003:4003"
    environment:
      TZ: "Europe/Moscow"
    extra_hosts:
      - host.docker.internal:host-gateway
    command: make server_start
    volumes:
      - /p/ptm/config/config.yaml:/p/ptm/config/config.yaml
      - /p/ptm/stat/web:/p/ptm/stat/web
```
В начале необходимо достать image из registry и только затем задеплоить в наш кластер:
```sh
docker pull docker-registry.ru:5000/ptm:stage;
docker stack deploy --with-registry-auth -c ./docker-compose.stage.yaml stage;
```
Все эти команды надо выполнять на ```manager``` node. Опция ```--with-registry-auth``` позволяет передать авторизационные данные на worker ноды, для того чтобы использовался один и тот же образ из регистра. ```stage``` это имя нашего стэка.

Посмотреть список стэков можно с помощью:
```sh
docker stack ls
NAME        SERVICES   ORCHESTRATOR
stage       1          Swarm
```
### 2. Установите для каждого из сервисов на стеке несколько реплик и разместите все их на мастер-ноде
Для этого мы будем использовать docker service для создания сервисов с несколькими репликами и параметром placement, чтобы ограничить их размещение на мастер-ноде.

Пример создания сервиса с несколькими репликами, который будет работать только на мастер-ноде:
```sh
docker service create \
  --name my_service \
  --replicas 3 \
  --placement 'node.role == manager' \
  nginx
```
Здесь:
```--replicas 3``` — указывает, что для сервиса будет создано 3 реплики.
```--placement 'node.role == manager'``` — ограничивает размещение сервисов только на мастер-ноде (manager node).
```nginx``` — это пример образа, который используется для сервисов.
### 3. Определите количество оперативной памяти на мастер-ноде и воркер-нодах
Для получения информации о памяти на нодах в Docker Swarm используем команду:
```sh
docker node ls
```
Затем используем:
```sh
docker node inspect <node-id> --format '{{.Description.Resources.MemoryBytes}}'
```
Это выведет информацию о количестве памяти для каждой ноды в байтах. Можно также получить более общую информацию о всех ресурсах:
```sh
docker node inspect <node-id> --format '{{json .Description}}' | jq .Resources
```
### 4. При помощи параметра placement разместите новый сервис на ноде с потреблением меньшего количества ресурсов
Для размещения нового сервиса на ноде с меньшими ресурсами можно использовать параметры ```--placement``` для указания, на какой конкретной ноде сервис должен быть размещен.

Пример команды для размещения сервиса на ноде с определенными характеристиками:
```sh
docker service create \
  --name my_optimized_service \
  --replicas 2 \
  --placement 'node.id == <node-id>' \
  --memory 256m \
  --cpu 0.5 \
  nginx
```
```--placement 'node.id == <node-id>'``` — ограничивает размещение сервисов на конкретной ноде с минимальным потреблением ресурсов.
```--memory 256m и --cpu 0.5``` — ограничивают ресурсы для каждого контейнера.
### 5. Установите зарезервированное и максимальное количество ресурсов для сервиса, выведите результаты проинспектировав сервис после деплоя
При создании сервиса можно установить резервированные и максимальные ресурсы:
```sh
docker service create \
  --name my_limited_service \
  --replicas 2 \
  --reserve-memory 128m \
  --limit-memory 512m \
  --reserve-cpu 0.2 \
  --limit-cpu 1.0 \
  nginx
```
Здесь:
```--reserve-memory 128m``` — резервирует 128 MB памяти для контейнера.
```--limit-memory 512m``` — устанавливает ограничение на 512 MB.
```--reserve-cpu 0.2``` — резервирует 0.2 CPU для контейнера.
```--limit-cpu 1.0``` — устанавливает ограничение на 1 CPU для контейнера.
После развертывания сервиса можно проверить статус с помощью:
```sh
docker service inspect --pretty my_limited_service
```
Это выведет информацию о сервисе, включая данные о ресурсах.
### 6. Создайте секрет и добавьте его к контейнеру с базой данных
Создание секрета в Docker:
```sh
echo "my_db_password" | docker secret create db_password -
```
Это создаст секрет с именем ```db_password```.

Далее, при создании контейнера с базой данных, добавим секрет:
```sh
docker service create \
  --name db_service \
  --secret db_password \
  mysql:latest
```
Здесь:
```--secret db_password``` — добавляет секрет db_password в контейнер с базой данных.
```mysql:latest``` — это образ для базы данных MySQL, который будет использоваться для контейнера.
После создания сервиса с базой данных, секрет можно будет использовать в контейнере, например, как переменную окружения или файл в контейнере.

Чтобы убедиться, что секрет был добавлен, можно выполнить команду:
```sh
docker service inspect --pretty db_service
```
Это покажет, что секрет был успешно добавлен к контейнеру.
